# Тесттер — шаблон сайта для тестов по дисциплинам

Статический сайт (без сервера и сборки): откройте `index.html` в браузере или выложите папку на любой хостинг (GitHub Pages и т. п.).

## Быстрый старт

1. Откройте `index.html` → «Зайти» → «✏️ Редактор дисциплин».
2. Создайте дисциплину, добавьте вопросы (формой или большим текстом).
3. Чтобы увидели все, а не только вы: **скачайте файл дисциплины** и `manifest.js` из редактора, положите в `data/`, загрузите на хостинг, увеличьте `DATA_VERSION` в `js/config.js`.

Демо-дисциплина (`data/disciplines/demo.js` + слово `"demo"` в `data/manifest.js`) нужна только как образец — удалите её.

## Старые вопросы

В папке `_old_questions/` лежат все 1071 вопрос из прежнего `quiz.js`, уже в новом формате (5 дисциплин). Чтобы вернуть их:
скопируйте `_old_questions/disciplines/*.js` в `data/disciplines/` и замените `data/manifest.js` файлом `_old_questions/manifest.js`.
В `finance` есть 50 точных повторов, в `philosophy` — 10, в `pccontroller` — 2: в редакторе есть кнопка «Удалить точные повторы».

## Структура

```
index.html   quiz.html   admin.html      ← только каркас; логика в js/
css/style.css                           ← все цвета в переменных (:root и [data-theme="dark"])
js/
  config.js   настройки и ВСЕ тексты интерфейса
  utils.js    el(), shuffle(), slugify(), download()
  store.js    вся работа с данными (файлы + localStorage + проверка вопросов)
  theme.js    тёмная/светлая тема и кнопка 🌙
  auth.js     флаг «вошёл» (НЕ защита, см. ниже)
  home.js     главная          quiz.js   движок теста        admin.js   редактор
data/
  manifest.js              список id дисциплин (порядок = порядок на главной)
  disciplines/<id>.js      вопросы одной дисциплины
```

## Три способа добавить дисциплину

| Способ | Как |
|---|---|
| Редактор | `admin.html` → «Новая дисциплина» → вопросы → скачать файлы → положить в `data/` |
| Вручную | скопировать `data/disciplines/demo.js` в `<id>.js`, заполнить, дописать `<id>` в `data/manifest.js` |
| Импорт | `admin.html` → «⬆ Импорт JSON» (понимает и резервные копии, и старый формат `{ключ: [вопросы]}`) |

Править `index.html`, `auth.js` или `quiz.js` **не нужно** — в старой версии новая дисциплина требовала правки в трёх местах.

## Формат вопроса

```js
{ question: "Текст", answers: [ {text: "Верный", correct: true}, {text: "Неверный", correct: false} ], explanation: "необязательно" }
```
Вариантов любое число (≥ 2). Несколько `correct: true` → вопрос с выбором нескольких ответов (засчитывается только полное совпадение).

Массовый ввод в редакторе:
```
? Вопрос
+ верный
- неверный
! пояснение (необязательно)

? Следующий вопрос …
```

## ⚠ Что НЕ удалять и не менять (чтобы всё не посыпалось)

| Что | Почему |
|---|---|
| Порядок `<script>`: `config → utils → store → theme → auth → скрипт страницы` | каждый файл использует предыдущие; при ошибке в консоли будет понятное сообщение (`Quiz.need`) |
| `id="app"` (index), `id="quiz"` и `id="categoryTitle"` (quiz), `id="admin"` (admin) | именно сюда JS рисует страницу |
| `<script>` в `<head>` с `localStorage.getItem('theme')` | тема применяется до отрисовки, без белой вспышки |
| `<meta name="viewport">` | без него мобильная вёрстка не включается (в старой версии его не было) |
| Ключи localStorage `isLoggedIn`, `theme`, `quiz.local.v1` (в `config.js → KEYS`) | у пользователей сохраняются вход, тема и правки редактора. Меняете формат — делайте `v2` и перенос из `v1` в `store.js → readLocal` |
| Обёртка `(window.QUIZ_DATA = window.QUIZ_DATA \|\| []).push({...})` в файлах дисциплин | по ней `store.js` находит дисциплину |
| `id` дисциплины = имя файла (латиница, цифры, `-`, `_`; регистр важен) | иначе файл не найдётся (`AI.js` ≠ `ai.js` на Linux-хостинге) |
| Параметр `?category=<id>` в ссылках | старые закладки продолжают работать |
| CSS-классы, которые создаёт JS: `.answer .multi .selected .correct .wrong .grid-question .current .answered-correct .answered-wrong .navigation-panel .toast .answer-row .q-item` | переименуете в CSS — переименуйте и в JS |
| Вывод текста через `textContent` / `el()`, а не `innerHTML` | иначе `<`, `&` в вопросах ломают страницу, а чужой импорт может выполнить скрипт |
| Проверки в `store.js` (`checkQuestion`, `normalizeDiscipline`) и в `quiz.js` (`total ? … : 0`) | защищают от вопроса без верного ответа, пустого теста, деления на 0 |

## Что было не так в исходном проекте (и как исправлено)

1. **Одна дисциплина = правки в 3 файлах** (`questions` в quiz.js, список в auth.js, `RANGE_SELECTOR_CATEGORIES`). Теперь всё из `data/` автоматически.
2. **Все 1071 вопрос в одном файле на 650 КБ**: одна пропущенная запятая — не работает ни одна дисциплина. Теперь файл на дисциплину, ошибка одного не мешает остальным, а на главной видно предупреждение (в т. ч. для файла с синтаксической ошибкой).
3. **`quiz.html` открывался без входа** — `auth.js` там не подключался. Теперь `Quiz.auth.guard()` на каждой странице. (Вход всё равно не защита, см. ниже.)
4. **Глобальный `button {…}` в CSS** — каждая новая кнопка получала кружок, ширину 100% и отступ; отсюда ~300 строк `!important`. Теперь вид кнопок — только через классы, тёмная тема — через переменные.
5. **`auth.js` перезаписывал `document.body.innerHTML`** и «возвращал тему» вручную; кнопка темы была продублирована в 3 HTML. Теперь её создаёт `theme.js` один раз.
6. **Выбор ответа искался по тексту** (`btn.textContent === selectedText`): при одинаковых вариантах подсвечивались оба (в `finance` такие есть). Теперь по id ответа.
7. **`find(a => a.correct).text`** падал на вопросе без правильного ответа. Теперь такие вопросы отсеиваются и попадают в предупреждение.
8. **Порядок ответов менялся при каждом возврате к вопросу**, а перемешивание `sort(() => Math.random() - 0.5)` неравномерное. Теперь Фишер–Йетс, порядок фиксируется на старте.
9. **Текст вопроса через `innerHTML`** — уязвимость (XSS) и поломка при `<`/`&`. Теперь `textContent`.
10. **Неверная категория**: `alert` + редирект, но код шёл дальше и падал на `category.toUpperCase()`. Теперь сообщение со ссылкой в меню. Заголовок теста — название дисциплины, а не `PCCONTROLLER`.
11. **Снегопад**: CSS его скрывал (`display:none`), но JS продолжал крутить анимацию; `snowInterval` — неявная глобальная переменная. Убран из шаблона.
12. **Нет `viewport`** — медиа-запросы для телефона не работали на реальных устройствах.
13. В результатах теперь есть **разбор ошибок**; добавлены клавиши `1–9` и `←/→`.

## Ограничения (честно)

- **Вход «Зайти» — не защита.** Флаг в localStorage, а `data/*.js` скачиваются напрямую по ссылке. Для приватных материалов нужен сервер.
- **Правки редактора живут в браузере** (≈5 МБ). Очистили данные сайта — пропали. Делайте «⬇ Резервная копия» и публикуйте файлами в `data/`.
- **Кэш браузера:** после замены файлов в `data/` увеличьте `DATA_VERSION` в `config.js`.
- Для публичной версии без редактора поставьте `ADMIN_ENABLED: false` (или не выкладывайте `admin.html` и `admin.js`) — это скрывает редактор, но не является защитой.

## Куда расширять без риска

- **Тексты / язык интерфейса** — только `config.js → T`.
- **Цвета и вид** — только переменные в `style.css`.
- **Таймер, режим экзамена, статистика ошибок** — в `quiz.js` (у каждого вопроса есть стабильный `q.id`; подсказки в шапке файла).
- **Новый тип вопроса** — `checkQuestion` (store.js) → `renderAnswers`/`isCorrect` (quiz.js).
- **Серверное хранение** — заменить только внутренности `store.js` (`load`, `saveDiscipline`…): страницы обращаются к данным лишь через `Quiz.store`.
- **Новая страница** — скопируйте любой HTML, сохраните порядок скриптов и вызовите `Quiz.auth.guard()` первой строкой своего скрипта.
